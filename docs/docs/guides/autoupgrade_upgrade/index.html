Upgrade of PDBs with AutoUpgrade (Unplug/Plug)

Important
 The upgrade of PDBs is experimental.
Supported is the Unplug/Plug upgrade of PDBs from a CDB of the old release (e.g. 19c) into an existing CDB of the new release (e.g. 26ai) on the same host.

The role autoupgrade upgrades PDBs with Oracle AutoUpgrade (autoupgrade.jar). AutoUpgrade unplugs the PDBs from the source CDB, plugs them into the target CDB and upgrades them there. The installation of AutoUpgrade and the general settings are described in autoupgrade.adoc.

The upgrade is split into 3 phases. The names are the AutoUpgrade modes:

Important
 The analyze phase is always the first step.
upgrade_deploy.yml executes upgrade_analyze.yml first and starts the upgrade only, when the analyze phase was successful.
The fixups phase is optional. It applies the fixups some time before the deploy and shortens the downtime. Without it, AutoUpgrade applies the fixups during the deploy.

1. End state in oracle_pdbs

oracle_pdbs always defines the end state of a PDB. For the upgrade this is the PDB in the target CDB of the new release:

  • cdb: the target CDB

  • home: the target ORACLE_HOME

The source of the PDB is defined with the attribute autoupgrade of the PDB. It is used by the role autoupgrade only.

Warning

Do not execute playbook manage_db between the change of oracle_pdbs and the upgrade!

As soon as a PDB in oracle_pdbs points to the target CDB, oradb_manage_pdb (playbook manage_db) tries to reach this end state. It does not know AutoUpgrade and creates a new, empty PDB in the target CDB instead of migrating the existing PDB.

  • The analyze phase detects this situation (PDB exists in source and target CDB, state conflict) and fails. The empty PDB must be dropped manually before the upgrade.

  • Execute manage_db again only after a successful upgrade (autoupgrade_upgrade.yml).

  • Prepare everything, which needs manage_db (e.g. the target CDB), before oracle_pdbs is changed.

2. Upgrade vs. Out-of-Place Patching

Both procedures move a database into a new ORACLE_HOME. They must not be mixed up.

oradb_manage_db refuses the switch of the ORACLE_HOME of a CDB, when the release of the old and the new ORACLE_HOME differs (oraversion -majorVersion).

3. Requirements

  • Source and target ORACLE_HOME are installed (db_homes_config, db_homes_installed, playbook swdb)

  • The source CDB is running from the source ORACLE_HOME

  • The target CDB exists and is running from the target ORACLE_HOME. It is created with playbook manage_db before the PDBs are changed in oracle_pdbs. 26ai supports Container Databases only.

  • AutoUpgrade (autoupgrade.jar) in the software repository. It is installed on the database server by the task files.

  • Java: the JDK of the target ORACLE_HOME is used, when autoupgrade_java_home is empty

  • AutoUpgrade is executed on the database server as oracle_user. The playbooks set autoupgrade_run_local: false. The task files fail with autoupgrade_run_local: true.

  • The Python module pexpect is not needed for the upgrade

  • Upgrade paths, minimum Release Updates, character sets, components etc. follow the rules of Oracle for AutoUpgrade

4. Configuration

4.1. Attribute autoupgrade in oracle_pdbs

Only PDBs with the attribute autoupgrade and state: present are processed.

Table 3. Attributes of autoupgrade in oracle_pdbs
Attribute Mandatory Description

source_cdb

yes

oracle_db_name of the source CDB. Must differ from cdb.

source_home

no

Key in db_homes_config of the source ORACLE_HOME. Default: home of source_cdb in oracle_databases. Mandatory, when the source CDB is not in oracle_databases.

source_sid

no

SID of the source CDB. Default: oracle_db_instance_name, oracle_db_unique_name or oracle_db_name of source_cdb in oracle_databases, otherwise source_cdb.

source_pdb_name

no

Name of the PDB in the source CDB. Default: pdb_name. A different name renames the PDB (upg1.target_pdb_name.<pdb>).

copy_option

no

upg1.target_pdb_copy_option.<pdb>, e.g. file_name_convert=NONE. Default: NOCOPY - the datafiles are reused, no fallback with the source CDB. See Datafiles: NOCOPY or copy.

restoration

no

true: Guaranteed Restore Point before the upgrade. Default: autoupgrade_upgrade_restoration (false)

parameters

no

Dict with AutoUpgrade parameters (upg1.<key>=<value>). Overrides autoupgrade_upgrade_parameters.

The target is taken from the PDB itself (end state):

  • cdb: target CDB. It must be defined in oracle_databases.

  • home: target ORACLE_HOME. It must be the same as home of the target CDB in oracle_databases.

Example: move ORCLPDB1 from DB2 (19c) into DB26 (26ai)
db_homes_config:
  db1932-si-ee:
    version: 19.3.0.0
    oracle_home: /u01/app/oracle/product/19/db_19.32
    edition: EE
    readonly_home: true
    oracle_home_name: db1932siee
  db26-si-ee:
    version: 26.1.0.0
    oracle_home: /u01/app/oracle/product/26/db_26.1
    edition: EE
    readonly_home: true
    oracle_home_name: db261siee

oracle_databases:
  - oracle_db_name: DB2          # source CDB in 19c
    home: db1932-si-ee
    state: present
    # ...
  - oracle_db_name: DB26         # target CDB in 26ai - created before the upgrade
    home: db26-si-ee
    is_container: true
    state: present
    # ...

oracle_pdbs:
  - cdb: DB26                    # end state: target CDB
    home: db26-si-ee             # end state: target ORACLE_HOME
    pdb_name: ORCLPDB1
    state: present
    autoupgrade:
      source_cdb: DB2            # source CDB
      parameters:
        timezone_upg: "yes"

4.2. AutoUpgrade jobs

All PDBs with the same source CDB and the same target CDB are upgraded in one AutoUpgrade job.

  • Config file: autoupgrade_home/cfg/upgrade_<source SID>_<target SID>.cfg

  • Log directory: autoupgrade_log_dir/<source SID>_<target SID>

  • restoration and parameters must be identical for all PDBs of a job

  • Only PDBs, which are still in the source CDB, are written into upg1.pdbs. An interrupted upgrade continues with the remaining PDBs.

5. Datafiles: NOCOPY or copy

During the Unplug/Plug upgrade AutoUpgrade unplugs the PDB from the source CDB into an XML file and creates the PDB in the target CDB with create pluggable database …​ using '<xml file>'. The attribute copy_option in oracle_pdbs (AutoUpgrade parameter target_pdb_copy_option.<pdb>) defines, what happens with the datafiles.

Table 8. Options for the datafiles
copy_option Datafiles Disk space Duration Fallback into the source CDB

not set (default)

NOCOPY: the target CDB uses the existing datafiles. They stay in their directory, e.g. oradata/DB2/<GUID>/datafile.

none

short, independent of the size

no - the datafiles are upgraded to the new release

file_name_convert=NONE

copied as Oracle Managed Files into db_create_file_dest of the target CDB

size of the PDB

copy of all datafiles

yes - the source datafiles stay unchanged

file_name_convert=('<old>', '<new>')

copied, <old> in the path is replaced by <new>

size of the PDB

copy of all datafiles

yes - the source datafiles stay unchanged

5.1. NOCOPY (default)

oracle_pdbs:
  - cdb: DB1
    home: db26-si-ee
    pdb_name: ORCLPDB1
    state: present
    autoupgrade:
      source_cdb: DB2
      # no copy_option => NOCOPY

  • Fastest way. Recommended for big PDBs, when a backup of the PDB exists.

  • After the upgrade the datafiles of the PDB in the target CDB are still in the directory of the source CDB, e.g. /u01/app/oracle/oradata/DB2/<GUID of the PDB>/datafile/. They can be moved later online with alter database move datafile in the target CDB.

  • There is no way back. Oracle: "Backups are the only fallback strategy." Flashback Database (restoration) does not work across the Unplug/Plug.

Warning

With NOCOPY the target CDB uses datafiles in the directories of the source CDB.
Do not remove these directories (e.g. rm -rf /u01/app/oracle/oradata/DB2), when the source CDB is dropped later. Check the datafiles of the target CDB first:

select name from v$datafile where con_id = (select con_id from v$pdbs where name = 'ORCLPDB1');

5.2. Copy as Oracle Managed Files

oracle_pdbs:
  - cdb: DB1
    home: db26-si-ee
    pdb_name: ORCLPDB1
    state: present
    autoupgrade:
      source_cdb: DB2
      copy_option: file_name_convert=NONE

  • Recommended for OMF and ASM (AutoUpgrade: "For ASM/OMF, use: file_name_convert=none").

  • The target CDB needs db_create_file_dest (or pdb_file_name_convert). Otherwise the analyze phase reports "The target database …​ requires the PDB_FILE_NAME_CONVERT or DB_CREATE_FILE_DEST system parameter defined when the target_pdb_copy_option config parameter is set to file_name_convert=NONE". Set it with init_parameters of the target CDB in oracle_databases.

  • The datafiles are created in the directory of the target CDB, e.g. oradata/DB1/<GUID>/datafile.

  • Needs disk space and time for a complete copy of the PDB. The downtime of the PDB includes the copy.

5.3. Copy with path conversion

oracle_pdbs:
  - cdb: DB1
    home: db26-si-ee
    pdb_name: ORCLPDB1
    state: present
    autoupgrade:
      source_cdb: DB2
      copy_option: "file_name_convert=('/u01/app/oracle/oradata/DB2/', '/u01/app/oracle/oradata/DB1/')"

  • For datafiles with fixed paths (no OMF). Each occurrence of <old> in the path of a datafile is replaced by <new>.

  • More than one pair is possible: file_name_convert=('/a/', '/x/', '/b/', '/y/').

  • The target directories must exist and must be writable for oracle_user.

  • Quote the value in YAML because of the brackets and quotes.

5.4. Fallback after a copy

With a copy the datafiles of the source PDB stay unchanged in the release of the source CDB. AutoUpgrade has unplugged the PDB into an XML file in the job directory:

<autoupgrade_log_dir>/<job>/<source SID>/<job number>/drain/<source SID>-<PDB>.xml

keep_source_pdb (AutoUpgrade parameter, set with parameters) controls the source CDB:

Table 9. keep_source_pdb
Value Source CDB after the upgrade

no (default)

The PDB is dropped from the source CDB (drop pluggable database …​ keep datafiles). The datafiles are kept.

yes

The PDB is kept in the source CDB in a closed state (AutoUpgrade: "kept in a closed state instead of being removed from the source CDB").

 
    autoupgrade:
      source_cdb: DB2
      copy_option: file_name_convert=NONE
      parameters:
        keep_source_pdb: "yes"

The role ignores PDBs with status UNPLUGGED in the source CDB. A kept source PDB is not reported as conflict.

The fallback itself is a manual task and is not implemented in the role:

  1. Drop the upgraded PDB from the target CDB, if needed (drop pluggable database ORCLPDB1 including datafiles - only with a copy, never with NOCOPY!)

  2. Plug the PDB into the source CDB again, e.g. with the XML file and the unchanged datafiles: create pluggable database ORCLPDB1 using '<xml file>' nocopy; and open it

  3. Change oracle_pdbs back to the source state

Note
 The fallback with keep_source_pdb and the copy options is not tested with molecule yet. Test the procedure before you use it in production.

5.5. Recommendation

Table 10. Which option to use
Situation Option

Big PDB, short downtime, backup available

NOCOPY (default)

Fallback into the source CDB needed, enough disk space

file_name_convert=NONE + keep_source_pdb: "yes"

OMF/ASM

file_name_convert=NONE

Fixed paths without OMF, new directory for the target CDB

file_name_convert=('<old>', '<new>')
Important
 Take a backup of the PDB before the deploy phase - independent of the option.

6. Process overview

  1. Preparation with manage_db (no downtime) - oracle_pdbs still points to the source CDB

    1. Install the target ORACLE_HOME with playbook swdb (db_homes_installed)

    2. Add the target CDB to oracle_databases and create it with playbook manage_db

  2. Change the inventory to the end state

    1. cdb and home of the PDBs in oracle_pdbs: target CDB and target ORACLE_HOME

    2. Add the attribute autoupgrade with source_cdb to the PDBs

    3. From now on: no manage_db until the upgrade is done!

  3. Analyze phase (no downtime): autoupgrade_upgrade_analyze.yml

    1. Install autoupgrade.jar on the database server

    2. Read the PDBs of the source and the target CDB (v$pdbs)

    3. AutoUpgrade analyze for the PDBs in the source CDB

    4. Evaluate the prechecks. Fail on errors without automatic fixup.

  4. Fix the reported problems and repeat the analyze phase until it is successful

  5. Fixups phase (no downtime, optional): autoupgrade_upgrade_fixups.yml

    1. AutoUpgrade fixups for the PDBs in the source CDB, e.g. some days before the deploy

    2. Evaluate the prechecks like the analyze phase

  6. Deploy phase (downtime of the PDBs): autoupgrade_upgrade.yml

    1. Analyze phase (again)

    2. AutoUpgrade deploy: prechecks, fixups, unplug, plug, upgrade, postupgrade

    3. Check that the PDBs are open READ WRITE in the target CDB

  7. Post tasks

    1. Execute playbook manage_db - the PDBs are in their end state now

    2. Remove the attribute autoupgrade from oracle_pdbs (optional - upgraded PDBs are skipped)

    3. Remove the source CDB, when it is not needed anymore (state: absent in oracle_databases)

8. Fixups phase

ansible-playbook -i inventory/ -e hostgroup=dbservers playbooks/autoupgrade_upgrade_fixups.yml

The fixups phase is the analyze phase with AutoUpgrade in mode fixups (upgrade_fixups.yml includes upgrade_analyze.yml):

  • Same checks of the source and the target CDB and the same states of the PDBs

  • AutoUpgrade executes the prechecks and applies the fixups (e.g. dictionary statistics, purge recyclebin) in the source CDB/PDBs. The PDBs are changed, but stay in the source CDB.

  • Same evaluation of the prechecks, logfiles and reports as the analyze phase. It fails on errors without automatic fixup.

The fixups phase is optional. Execute it some time before the deploy to shorten the downtime. Without it, AutoUpgrade applies the fixups during the deploy.

9. Deploy phase

ansible-playbook -i inventory/ -e hostgroup=dbservers playbooks/autoupgrade_upgrade.yml

# one PDB only
ansible-playbook -i inventory/ -e hostgroup=dbservers -e '{"autoupgrade_upgrade_pdbs": ["ORCLPDB1"]}' \
  playbooks/autoupgrade_upgrade.yml

upgrade_deploy.yml:

  1. executes the analyze phase (upgrade_analyze.yml)

  2. executes autoupgrade.jar -config upgrade_<job>.cfg -mode deploy -noconsole for each job in state analyzed (async: autoupgrade_upgrade_timeout, poll: autoupgrade_upgrade_poll)

  3. checks that all PDBs of the job are open READ WRITE in the target CDB and are gone from the source CDB

The jobs are executed one after the other.

Follow the progress on the database server
tail -f /u01/app/oracle/cfgtoollogs/autoupgrade/DB2_DB1/cfgtoollogs/upgrade/auto/autoupgrade.log

9.1. Repeated execution

  • PDBs in the target CDB are skipped (state upgraded). The playbook can be executed again without changes.

  • An interrupted or failed deploy is resumed by the next execution of autoupgrade_upgrade.yml, see Recovery data of AutoUpgrade.

9.2. Recovery data of AutoUpgrade

AutoUpgrade keeps recovery data after each deploy in autoupgrade_log_dir/<job>/cfgtoollogs/upgrade/auto (config_files/upgradeJobs.bin, state.txt) - for a finished deploy as well as for an interrupted or failed one. As long as the recovery data exists, AutoUpgrade refuses analyze, fixups and a new deploy with the same config file:

There is an unfinished execution of a deploy mode. Run the AutoUpgrade in deploy mode to resume from failure point

9.3. Fallback

  • See Datafiles: NOCOPY or copy: a fallback into the source CDB is possible with a copy of the datafiles only.

  • restoration: true / autoupgrade_upgrade_restoration: true: AutoUpgrade creates a Guaranteed Restore Point (upg1.restoration=yes). Requires a Fast Recovery Area and Enterprise Edition. Check the Oracle documentation, how the restore point is used for an Unplug/Plug upgrade.

The fallback is not implemented in the role.

Important
 Take a backup before the upgrade.

10. After the upgrade

oracle_pdbs describes the end state already. Nothing has to be changed for the PDBs.

  • Execute playbook manage_db. It manages the PDBs in the target CDB now (tablespaces, users, services, …​).

  • The attribute autoupgrade can be removed from oracle_pdbs. Upgraded PDBs are skipped anyway.

  • Services, tnsnames.ora entries and wallets, which point to the source CDB, must be changed to the target CDB.

  • Remove the source CDB, when it is not needed anymore (state: absent in oracle_databases), and the source ORACLE_HOME (db_homes_installed).

Warning
 Do not execute task converge S=upgrade during or after the deploy phase without task destroy S=upgrade. Important
 side_effect.yml must never import playbook manage_db. With oracle_pdbs in the end state it would create an empty ORCLPDB1 in DB1 (see warning above).

12. Known limitations

  • Unplug/Plug upgrade of PDBs into an existing CDB on the same host only. Upgrade of a whole CDB, non-CDB to PDB conversion, RAC, Oracle Restart and Data Guard are not supported.

  • The jobs are executed one after the other. AutoUpgrade can execute jobs in parallel - not used by the role.

  • The fallback is not implemented in the role.

  • manage_db must not be executed between the change of oracle_pdbs and the upgrade (see warning above).

  • The evaluation of the prechecks depends on *_checklist.json, which is not documented by Oracle.

  • Patching of databases with AutoUpgrade (-patch) is not implemented.
